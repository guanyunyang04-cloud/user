# T0 Project 当前判断

快照日期：`2026-04-12`

## 1. 角色定位
- `t0_project` 是工作区内的盘中执行、执行抽象与 RL 方向实验分脑。
- 它服务于研究原型验证，不是当前正式生产主线。

## 2. 当前状态
- 本分脑已经接入主脑统一附着合同与接管快路。
- 当前重点仍在：
  - 执行抽象边界
  - `paper` 路径
  - RL 原型验证
- 当前 `live` 仍是保护性骨架，不应视为已打通真实自动执行。

## 3. 当前优先级
- 保持 `t0_project` 与 `daily_research` 正式生产主线隔离。
- 继续把盘中执行研究定位为实验原型，而不是静默升级为可部署系统。
- 若继续推进真实执行能力，先补齐执行抽象层的可验证边界。
- 保持 brain 与 body 高匹配，避免实验代码与脑内状态脱节。

## 4. 当前边界
- `live` 不是已打通的真实自动交易。
- 本分脑结论不得直接替代 `daily_research` 默认执行结论。
- 真实接口讨论必须遵守：
  - `paper -> 人工确认 -> 真实接口`

## 5. 当前主问题
- 当前主问题不是“如何尽快接真实接口”。
- 当前主问题是：
  - 如何在不污染正式生产主线的前提下，
  - 保留盘中执行与 RL 的可接管研究空间。

## 6. 当前风险
- 容易把实验结论误读成生产结论。
- 容易跳过执行抽象边界，直接讨论真实下单。
- 如果不持续写回，本分脑会重新退化成“代码有、状态无”。

## 7. 推荐下一步
- 若继续推进本分脑，先补连续时间证据链与接入前检查清单。
- 先证明抽象层和 `paper` 路径可复现，再讨论真实接口。
- 所有跨到 `daily_research` 的判断，都先回主脑和该分脑重新确认。
