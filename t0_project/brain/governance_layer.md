# T0 Project 治理层

快照日期：`2026-04-12`

## 1. 治理目标
- 防止实验分脑越级影响正式生产主线。
- 保持 `paper / live / RL / strategy` 的边界清晰。
- 保证盘中执行研究始终走“可验证抽象优先”的路径。

## 2. 标准闭环
1. `Wake`
   - 先读身份层和交接包。
2. `Locate`
   - 判断当前任务属于执行抽象、`paper` 路径、RL 原型还是底层交互。
3. `Choose`
   - 选当前最该补的一段证据或边界。
4. `Preflight`
   - 过执行前四检。
5. `Act`
   - 产出动作结果、证据、新事实和风险变化。
6. `Reflect`
   - 判断哪些信息要进入 lesson、rule、handoff。
7. `Replan`
   - 若结果改写路径，立刻更新当前判断和下一步。

## 3. 执行前四检
- 目标一致性检查：
  - 这件事是否仍属于实验分脑职责，而不是生产替代。
- 规则冲突检查：
  - 是否违反 `paper -> 人工确认 -> 真实接口` 顺序。
- 经验教训检查：
  - 是否踩中“把实验骨架误当成真实能力”的已知失败模式。
- 依赖完整性检查：
  - 当前证据链、抽象边界、上下文和资源是否足够。

## 4. 偏移信号
- 目标偏移：
  - 把实验目标误写成生产目标。
- 上下文偏移：
  - 把保护性 `live` 骨架当成已打通能力。
- 行为偏移：
  - 还没补验证链，就先讨论全自动真实接口。
- 认知偏移：
  - 把局部实验结果讲成整体可部署系统。

## 5. 修复分级
- 轻度偏移：
  - 刷新交接包和当前边界。
- 中度偏移：
  - 回退到 `paper` 路径，补齐验证链。
- 重度偏移：
  - 冻结真实接口讨论，只允许继续做抽象层与证据链工作。

## 6. 守卫
- 先接主脑，再接本分脑，不跳过脑结构直接看 body。
- 所有跨到 `daily_research` 的任务都先回主脑确认边界。
- 重要结构变更后，继续跑统一 brain 守卫与接管检查。

## 7. 写回纪律
- 当前实验定位与主问题写回 `working_memory.md`。
- 当前最小完备接管状态写回 `handoff_packet.md`。
- 新边界、新教训和新失败模式写回 `lesson_memory.md` 与 `rule_memory.md`。
- 时间顺序过程和证据写回 `episodic_memory.md`。
