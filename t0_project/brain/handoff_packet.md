# T0 Project 标准交接包

快照日期：`2026-04-12`

## 1. 角色定位
- 这是盘中执行、执行抽象与 RL 实验分脑的标准交接包。
- 它服务于研究接管，不服务于生产默认切换。

## 2. 当前状态摘要
- `t0_project` 是实验分脑，不是正式生产主线。
- 当前重点在：
  - 执行抽象
  - `paper` 路径
  - RL 原型验证
- 当前 `live` 仍是保护性骨架。

## 3. 当前主问题
- 当前主问题是：
  - 如何在不越级影响正式主线的前提下，
  - 让盘中执行与 RL 研究保持可接管、可验证、可复盘。

## 4. 已完成基础
- 本分脑已接入主脑。
- strategy、execution abstraction、RL、底层交互的 body_map 已明确。
- 当前接管结构已升级为：
  - `identity / handoff / rule / lesson / temporal / governance`

## 5. 未完成动作
- 还没有连续时间证据链。
- 还没有打通真实自动交易接口。
- 还没有形成“从实验到真实接口”的稳定晋升路径。

## 6. 关键风险
- 容易把实验阶段结论讲成生产结论。
- 容易跳过抽象层，直接讨论真实接口。
- 容易把保护性 `live` 骨架误读成完整能力。

## 7. 必守规则
- 必须先 `paper`，再人工确认，最后才讨论真实接口。
- 若会影响 `daily_research`，必须回主脑和对应分脑重新确认。
- 研究结果默认写回 brain，不写在聊天上下文里。

## 8. 推荐下一步
- 若下一步继续推进 `t0_project`，先补连续时间证据链。
- 先建立接入前检查清单，再讨论真实接口能力。
- 先把实验边界讲清，再扩执行能力。

## 9. 置信度与不确定性
- 高置信度：
  - 当前 `t0_project` 仍应被视为实验分脑。
- 中置信度：
  - 若后续补齐证据链与抽象边界，它可以继续承接更深的盘中执行研究。
