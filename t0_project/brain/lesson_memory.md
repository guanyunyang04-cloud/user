# T0 Project 教训记忆

快照日期：`2026-04-12`

## L001 - 盘中实验不能越级接管正式主线
- 事件：
  - `t0_project` 和 `daily_research` 在同一工作区内长期共存。
- 场景：
  - 盘中实验出现阶段性看起来更强的局部结果时。
- 根因：
  - 容易把实验验证和正式生产判决混在一起。
- 信号：
  - 用“更灵活”“更快”去替代 formal / recent / live 正式证据。
- 影响：
  - 生产主线可能被实验分支静默污染。
- 修复：
  - 强制把 `t0_project` 定位为独立实验分脑。
- 预防：
  - 若影响正式主线，必须回到主脑和 `daily_research` 分脑落盘。
- 升级动作：
  - 写入身份层和规则记忆。

## L002 - 真实接口前先做可验证抽象
- 事件：
  - 盘中系统很容易从信号直接跳到真实接口接入。
- 场景：
  - execution 抽象层尚未稳定时。
- 根因：
  - 忽略了订单、风控、适配器和确认流程的独立价值。
- 信号：
  - 想直接接自动下单，但中间抽象与保护层不完整。
- 影响：
  - 风险边界模糊，接管和验证都困难。
- 修复：
  - 固定 `paper -> 人工确认 -> 真实接口` 顺序。
- 预防：
  - 先补抽象层和风控，再讨论自动化。
- 升级动作：
  - 写入 action system 和 governance layer。
