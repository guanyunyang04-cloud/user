# 主脑治理层

快照日期：`2026-04-12`

## 1. 治理目标
- 监督脑网络是否偏离工作区北极星和统一合同。
- 保证关键状态、规则、计划、风险和交接信息始终外显。
- 在结构漂移、状态过期、交接失真时，强制触发修复。

## 2. 标准闭环
1. `Wake`
   - 先读取身份层和交接包。
2. `Locate`
   - 判断当前任务属于哪个分脑、哪个阶段、哪一类问题。
3. `Choose`
   - 选当前最该做的一件事。
4. `Preflight`
   - 过执行前四检。
5. `Act`
   - 执行动作并保留证据。
6. `Reflect`
   - 把结果沉淀为事实、经验、规则或教训。
7. `Replan`
   - 若结果改写路径，立刻更新当前判断和下一步。

## 3. 执行前四检
- 目标一致性检查：
  - 这件事是否仍服务工作区北极星和当前主问题。
- 规则冲突检查：
  - 是否违反主脑合同、分脑边界或统一接管顺序。
- 经验教训检查：
  - 是否踩中主脑或分脑已知失败模式。
- 依赖完整性检查：
  - manifest、brain 文件、body 入口和守卫链路是否足够完整。

## 4. 偏移信号
- 目标偏移：
  - 做着做着忘了主线分脑和当前工作区真实目标。
- 上下文偏移：
  - 把旧 packet、旧入口或旧合同当现状。
- 行为偏移：
  - 改了结构却不改 manifest，不改 manifest 却不跑守卫。
- 认知偏移：
  - 把主脑当项目事实库，或把分脑当跨项目规则库。

## 5. 修复分级
- 轻度偏移：
  - 刷新主脑交接包、当前判断和目标分脑入口。
- 中度偏移：
  - 回退到最近稳定合同，重做结构审阅和接管顺序检查。
- 重度偏移：
  - 冻结相关结构变更，只允许先修 manifest、brain 文档和守卫链路。

## 6. 守卫
- `doc_guard.py check`
  - 检查脑文件结构、manifest 与时间序列纪律。
- `brain_bootstrap.py`
  - 检查主脑优先的接管顺序是否仍可执行。
- 所有结构升级都必须满足：
  - manifest 可解析
  - read order 可执行
  - write route 可追踪
  - handoff packet 可读取

## 7. 写回纪律
- 工作区级身份、禁区与拓扑写回主脑。
- 分脑内部事实、证据和当前结论写回对应分脑。
- 当前交接摘要写回 `brain/handoff_packet.md`。
- 当前工作区判断写回 `brain/working_memory.md`。
- 任何结构升级完成后，都必须同步更新架构文档、manifest 和守卫结果。
