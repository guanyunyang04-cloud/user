# Daily Research Handoff Rules

快照日期：`2026-04-11`

## 1. 规则定位
- 本文件记录当前对所有 agent 都生效的接管纪律。
- 这些规则优先级高于旧实验习惯、旧 runner 习惯和“先最小改动再说”的默认倾向。
- 后续 agent 接管时，应在 `procedural_memory.md` 之前或同时阅读本文件。
- 当前标准接管起点已经前移到：
  - `identity_layer.md`
  - `handoff_packet.md`
  - `rule_memory.md`
  - `lesson_memory.md`
  - `temporal_state.md`

## 2. 实验纪律
- 所有正式实验都必须具备续训能力。
- 最低要求是支持同一 `experiment-tag / run_dir` 的 `strict resume`。
- 如果同模型还要继续加预算，只允许 `strict resume`，不允许 fresh rerun 代替。
- 没有续训路径的实验脚本、训练脚本或 pipeline，不算完成。

## 3. 运行纪律
- 长实验只允许前台执行。
- 不再默认使用后台 runner、后台监控器或 detached 训练。
- 终端直接发起的长实验，默认超时预算按 `10` 小时处理。
- 若 `10` 小时仍不够，再由用户显式决定是否继续放宽。

## 4. 改动原则
- `2026-04-11` 用户再次明确确认：改法不应追求最小，而应优先追求最有效。
- 改法不应追求最小，而应优先追求最有效。
- 如果“更小改动”和“更有效解决主问题”发生冲突，默认选更有效的方案。
- 只要风险可控、语义收口、能同步更新代码与 brain，就不应为了保守而故意做成低效小修。

## 5. 交接要求
- 新 agent 接管时，必须显式遵守本文件中的续训、前台和超时纪律。
- 新 agent 接管时，不再默认直接从 `episodic_memory.md` 起步；应先读取标准交接包和时态状态。
- 标准交接包至少要包含：
  - 当前状态摘要
  - 当前正在处理的问题
  - 已完成动作及证据
  - 未完成动作
  - 已知风险
  - 最近失败教训
  - 相关规则
  - 推荐下一步
  - 禁止重复尝试的无效路径
  - 置信度与不确定性说明
- 若后续用户再次修改这些纪律，应优先更新本文件，再继续实验或重构。
