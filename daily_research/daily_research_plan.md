# Daily Research 研究总纲

## 1. 文档分工
- `README.md`
  - 说明项目当前状态、目录结构、运行入口与维护命令；
- `daily_research_plan.md`
  - 说明当前主线、未解问题、优先级与停止规则；
- `research_log.md`
  - 记录按时间推进的实验、参数、结果与结论。

三者边界：

- `daily_research_plan.md` 解决“接下来做什么、为什么做”；
- `research_log.md` 解决“之前做过什么、证据是什么”。

## 2. 阶段总结
自立项以来，项目已经经历四个阶段：

1. `2026-03-14 ~ 2026-03-18`
  - 建起 `baseline`，完成 `score + 5d`、市场状态过滤、状态内权重等第一阶段收敛。
2. `2026-03-18 ~ 2026-03-20`
  - 引入 `advanced_ml`，并把执行端统一到“盘后信号 -> 次日开盘执行”。
3. `2026-03-20 ~ 2026-03-22`
  - `deep_alpha` 进入正式研究框架：历史滚动高流动性股票池、`next_open`、多窗口 walk-forward。
4. `2026-03-22`
  - 完成项目治理：Git 纳管、归档规则、入口去重、文档分工重整。

当前阶段已经不是“继续扩分支”，而是“稳定交付主线 + 克制推进研究主线”。

## 3. 当前项目判断

### 3.1 交付主线已经明确
- 当前唯一冻结的可执行主线是：
  - `advanced_ml + liquid500 + next_open`
- 这条线负责：
  - 每日盘后更新股票池；
  - 更新执行模型；
  - 生成次日开盘执行建议。

### 3.2 正式研究口径已经明确
- 正式研究必须使用：
  - 历史滚动 `liquid500 / liquid800`
  - `next_open`
  - 多窗口 walk-forward
- 这套口径用于判断研究结果能否接近执行端。

### 3.3 `deep_alpha` 已成为研究主线
- `deep_alpha` 不再是烟测分支，而是正式研究主线；
- 但它仍然只属于研究，不属于执行；
- 任何结论都必须在正式框架下成立，才有资格讨论晋级。

### 3.4 项目治理已经成为长期要求
- 当前目录已经纳入 Git；
- `cache` 与 `output` 已建立热区与冷归档规则；
- 后续项目维护不再依赖人工记忆，而依赖明确规则。

## 4. 当前固定主线

### 4.1 执行线
- 主线：
  - `advanced_ml + liquid500 + next_open`
- 股票池：
  - 每日盘后刷新 `liquid500_latest.txt`
- 执行方式：
  - 盘后生成计划，次日开盘手工执行

### 4.2 可解释基线与 `advanced_ml`
- 当前已确认有效的基础框架：
  - `score + 5d`
  - 市场状态过滤
  - 上涨双象限白名单
  - 风格约束
- 当前最接近可用的增强候选：
  - `up_low_breakout_v2`
- 当前不晋级的方向：
  - `up_dual_v1 / up_dual_v2`

### 4.3 `deep_alpha`
- 当前正式研究主线：
  - `patch-based masked pretraining + return ranking fine-tune`
- 当前正式评价框架：
  - rolling `liquid500`
  - `next_open`
  - multi-window walk-forward
- 当前状态：
  - 比早期方案更强；
  - 但仍未稳定赢过执行参考基线；
  - 部分关键窗口仍存在 `undertrained` 问题。

## 5. 已确认结论

### 5.1 基线与 `advanced_ml`
- `score + 5d` 显著优于 `equal + 1d`
- 市场状态过滤有效
- `trend_up_low_vol` 与 `trend_up_high_vol` 的双上涨白名单优于更保守版本
- `up_low_breakout_v2` 是当前唯一仍值得保留的增强候选
- `advanced_ml` 已经足够稳定，适合作为执行主线
- 但当前执行主线在最新正式子窗口 `2025-09-05 -> 2026-03-19` 已明显转弱，因此执行方向研究需要重启
- 第一轮正式修复扫描已经给出较明确方向：
  - 仅在 `trend_up_low_vol` 下下调 ML 主导权重有效；
  - 单独收紧 `turnover_limit=1.0 + min_hold_days=3` 并不能修复弱窗口，反而会拖累整体表现；
  - 当前最稳候选是 `ml=0.55 / none=0.25 / v2=0.20`
- 第二轮正式扫描进一步确认：
  - 在原 `regime_ma_window=60` 框架里，`0.55 / 0.25 / 0.20` 仍是 `0.55 ~ 0.60` 区间内最优点；
  - 但比权重微调更强的新信号是：`regime_ma_window=50` 的 `baseline` 在三个正式窗口里都优于当前执行主线；
  - 因此执行端修复的第一优先级已经上移到“复验并确认 `ma50` 状态启停候选”。
- 当前冻结决策同步明确为：
  - 执行端默认值暂不切换，继续冻结为：`advanced_ml + liquid500 + next_open`
  - 新的“最强正式修复候选”已经从第一轮的 `ma60 + up_low_ml55_none25_v220`，更新为第二轮的 `ma50 baseline`
  - `ma60 + up_low_ml55_none25_v220` 仍保留为次一级备选

### 5.2 `deep_alpha`
- `Transformer` 路线优于 `GRU`
- 直接做结构增强、辅助任务、原型约束等方案都不足以稳定晋级
- 预训练预算对结果影响很大，不能只看低预算版本就下最终结论
- 更轻的正式框架配置能显著提升本机研究吞吐，但不改变晋级标准

### 5.3 项目治理
- 文档分工必须保持单一职责；
- `output` 与 `cache` 不再默认长期热存；
- 生成物与源码必须分开管理。

## 6. 当前未解问题

### 6.1 `deep_alpha` 仍未拿到最终判决
- 当前 `12` 轮预训练版本虽然改善了弱窗口；
- 但仍未稳定保护原本更强的窗口；
- 且窗口 `1` 与 `3` 的预训练诊断仍提示 `undertrained`。

### 6.2 强窗口保护仍然不足
- 研究方案不能只追求修复最弱窗口；
- 还必须避免破坏当前已经表现较强的区间。

### 6.3 执行线需要持续稳态维护
- `advanced_ml` 虽然已经冻结为执行主线；
- 但仍需要通过正式研究口径持续复核，防止主线在研究推进中被静默偏离。

### 6.4 执行端近期收益能力转弱
- 在最新正式子窗口 `2025-09-05 -> 2026-03-19` 中，当前执行主线出现：
  - 超额收益为负；
  - 超额 Sharpe 为负；
  - 超额回撤过深。
- 这说明当前执行端虽然长期仍有效，但近期收益能力已经不理想。
- 因此后续不能只把重点放在 `deep_alpha` 晋级，也必须同步重启执行方向研究。
- 第一轮正式修复扫描结果表明：
  - 弱窗口问题主要不是股票池问题；
  - 也不宜先把重点放在更严的换手约束；
  - 更值得继续深挖的是 `trend_up_low_vol` 下的分段集成权重与状态启停阈值。
- 第二轮结果表明：
  - 在“状态启停阈值”这条线上，`regime_ma_window=50` 已经跑出了比单纯权重微调更强的整体结果；
  - `regime_ma_window=40` 又明显偏紧；
  - 因此下一轮不再盲扫更严阈值，而是围绕 `ma50` 做确认与边界复验。
- 第三轮 `ma50 baseline` 专项复验已经确认：
  - `ma50 baseline` 同时优于当前 `ma60 baseline` 与次一级备选 `ma60 + up_low_ml55_none25_v220`；
  - 相对这两个对照，`ma50 baseline` 都在 `17` 个季度里赢下 `13` 个季度，最强季度对正向季度总优势的占比约 `20%`，不是单季度异常抬升；
  - 在 `ma50` 框架内部，继续叠加 `up_low_ml55_none25_v220` 会明显伤害全样本与最近完整窗口，因此第四轮权重微调不再是立即优先项。
- 第五轮 `ma50` 边界稳定性与轻量风险控制复验表明：
  - `ma48` 跑出了比 `ma50` 更高的聚合结果，其中 `ma48 + take20` 是当前数值最强点；
  - 但它相对 `ma50 baseline` 只在 `17` 个季度里的 `5` 个季度更强，且 `2025Q3` 占了约 `54.92%` 的正向季度总优势；
  - `ma48` 内部 `take20` 的增益本身也高度集中，因此这条线当前更像“高收益待复验候选”，还不足以直接取代 `ma50 baseline` 的稳定头号位置；
  - `ma50` 内部的轻量风控只带来很小弱窗口改善，不足以改变当前主判断。

## 7. 下一步优先级

### 优先级 A：重启执行方向研究
目标：

- 在不放松正式框架的前提下，修复当前执行主线在最近窗口的失效与回撤问题。

具体动作：

1. 固定正式框架不变：
   - 历史滚动 `liquid500`
   - `next_open`
   - 多窗口 walk-forward
2. 先诊断当前执行主线在 `2025-09-05 -> 2026-03-19` 的失效来源：
   - 是否是状态过滤失真；
   - 是否是集成权重过于激进；
   - 是否是回撤控制与换手约束不足。
3. 第一轮修复优先围绕当前执行线本身：
   - `advanced_ml` 集成权重
   - 交易约束
   - 风险控制
   - 状态启停
4. 第一轮扫描后的下一步聚焦收敛为：
   - 继续细化 `trend_up_low_vol` 的分段集成权重；
   - 再评估状态启停阈值；
   - 暂不把更严的换手约束作为第一优先修复方向。
5. 第二轮扫描后的当前顺序调整为：
   - 先对 `regime_ma_window=50` 做专门复验；
   - 再决定是否还需要在 `ma50` 框架里叠加 `trend_up_low_vol` 分段权重微调；
   - `ma60` 下的权重微调保留为已知可用备选，而不是当前头号候选。
6. 在没有更强证据前，不先改执行股票池，因为当前 `liquid500` 仍是高流动性池中超额 Sharpe 最优的选择。
7. `2026-03-22` 之后的下一阶段研究排程固定为三轮：
   - 第三轮：`ma50 baseline` 专项复验
   - 第四轮：仅在 `ma50` 框架里检查 `trend_up_low_vol` 分段权重是否还能带来净增益
   - 第五轮：只做 `ma50` 框架内的状态边界与轻量风险控制复验，不回到“先收紧换手”这条线
8. 第三轮：`ma50 baseline` 专项复验的检查项固定为：
   - 是否在完整正式窗口、最新弱窗口、季度归因三层口径下都继续优于当前 `ma60 baseline`
   - 是否仍然优于次一级备选 `ma60 + up_low_ml55_none25_v220`
   - 是否在活跃比例、换手、持仓数、超额回撤上保持可解释，而不是只靠某一个季度异常放大
9. 第四轮：只有在第三轮复验通过后才启动，并且只允许做小范围微调：
   - 固定 `regime_ma_window=50`
   - 固定股票池、交易口径与其他状态配置不变
   - 只在 `trend_up_low_vol` 内部比较少量候选权重，目标是确认“`ma50 baseline` 是否已经足够好”，而不是为了调参而调参
10. 第五轮：边界复验只围绕状态启停本身展开：
   - 优先检查 `ma50` 附近的边界稳定性，而不是重新大范围盲扫
   - 优先检查状态活跃区间与回撤控制是否还有低成本改进空间
   - 若结果只是改善单个弱窗口、却破坏前三层正式指标，则立即停止
11. 三轮共同的产出要求固定为：
   - 每轮都生成独立输出目录、汇总表和归因结果
   - 每轮都把结论写回 `research_log.md`
   - 只有在连续复验后仍成立的候选，才允许进入“是否考虑替换执行默认值”的讨论
12. 在上述三轮结束前，当前执行决策不变：
   - 执行端默认值继续冻结为：`advanced_ml + liquid500 + next_open`
   - `ma50 baseline` 是当前头号正式修复候选
   - `ma60 + up_low_ml55_none25_v220` 只作为次一级备选保留
13. 第三轮专项复验完成后的当前顺序更新为：
   - 先进入第五轮：围绕 `ma50` 做状态边界稳定性与轻量风险控制复验
   - 第四轮 `trend_up_low_vol` 权重微调改为条件触发：只有在第五轮结果出现局部短板、且边界问题不能解释时才回头启动
   - `ma60 + up_low_ml55_none25_v220` 继续作为已知可用备选保留，但不重新升回头号方向
14. 第五轮完成后的当前顺序再次更新为：
   - 头号正式修复候选仍保持为 `ma50 baseline`，因为它当前是“收益-稳定性”更均衡的方案
   - 新增一条高收益待复验分支：`ma48 baseline`，并把 `ma48 + take20` 视为其附加轻量风控版本，而不是单独晋级
   - 下一步优先做 `ma48` 的专门稳定性复验与季度集中度诊断，而不是直接改执行端默认值
   - `ma60 + up_low_ml55_none25_v220` 继续作为保守已知备选保留

## 8. 停止规则
以下情况一律不晋级执行端：

1. 只在单个窗口改善，却破坏原本更强窗口；
2. 只在静态最新股票池上好看，未通过历史滚动股票池验证；
3. 只在单次样本或烟测中有效，未通过多窗口 walk-forward；
4. 训练诊断仍显示关键窗口 `undertrained`；
5. 结论无法用 `research_log.md` 中的实验记录回溯。
