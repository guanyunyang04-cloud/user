# Daily Research 执行控制台使用教程

## 1. 使用前提

- 所有 `daily_research` 程序都必须在 `yolos` 环境下运行。
- 依赖环境真源是 `daily_research/environment.yml`。
- 如果本机环境刚调整过，先同步环境：

```powershell
conda env update -f daily_research/environment.yml --prune
```

## 2. 启动方式

推荐直接使用独立入口：

```powershell
conda run -n yolos python daily_research/execution/run_execution_web.py --port 8765
```

也可以通过统一应用入口启动：

```powershell
conda run -n yolos python daily_research/execution/run_execution_app.py web --port 8765
```

启动后在浏览器打开：

```text
http://127.0.0.1:8765
```

说明：

- 控制台默认只监听 `127.0.0.1`。
- 不要改成公网地址对外暴露。

## 3. 页面说明

### 总览

- 查看当前作业、锁状态、`yolos` 解释器、active manifest、最近作业和最新交易计划。

### 任务

- 从任务注册表里选择任务。
- 填表后以后台方式提交。
- 适合触发 `trade-plan`、`candidate-trade-plan`、`candidate-backtest` 等任务。

### 作业

- 查看最近作业列表。
- 自动刷新，适合确认作业是否从排队中进入运行中并最终结束。

### 作业详情

- 查看 stdout / stderr 尾部。
- 查看命令、解释器、标签、退出码。
- 对失败或阻塞作业执行恢复。

### 体检

- 检查环境、manifest、持仓文件、运行时目录、Web 依赖和产物文件是否正常。

### 交易计划

- 预览 `latest_trade_plan.txt`。

### 连续策略

- 查看连续型组合策略代理的最新训练、评估、影子导出和运行时状态。
- 正式运行默认优先走 `continuous-policy-protocol`。
- 训练后端已拆成四类：
  - `formal_torch_v2`：GPU / `>=32` epoch / `strict resume` 的正式候选后端
  - `formal_torch_seq_v3`：更强的时序正式候选后端，沿同一套 GPU / `>=32` epoch / `strict resume` 合同运行
  - `formal_torch_hier_v4`：带 market / portfolio / cross-section interaction 的分层时序正式候选后端，同样遵守 GPU / `>=32` epoch / `strict resume`
  - `prototype_gbdt_v1`：只做 shadow / teacher / ablation 的非 epoch 原型
- 当前 protocol 支持 `balanced_v2 / swing_v2 / defensive_v2` 三种 lifecycle label preset。
- 当前推荐先从 `swing_v2` 开始，因为它是 r2 三预设里收益 / Sharpe 最强的 shadow 参考，但仍然不是可 promotion 的 live 替代。
- 当前仍是 shadow 模式，不会静默替换 live 默认执行链路。

### 模拟账户

- 在前端维护 `available_cash` 与模拟持仓。
- 保存后会写回 `daily_research/execution/current_positions.csv`。
- 也可以一键重置为示例账户。

### 使用教程

- 查看控制台的上手流程、恢复方法和高风险提示。

### 运行时

- 查看锁状态、活动线程、运行时告警和 JSON 快照。
- 在确认旧作业已经失效后，可以执行强制解锁。

## 4. 推荐操作顺序

1. 先打开“体检”页，确认状态为正常。
2. 再去“任务”页提交目标任务。
3. 提交后进入“作业详情”页观察日志。
4. 作业结束后到“交易计划”或相关产物页确认结果。
5. 如果失败，再根据 stderr 和运行时状态决定是否恢复。

## 5. 常见操作

### 5.1 生成默认交易计划

- 页面路径：`任务`
- 任务名：`trade-plan`
- 常见做法：直接提交，或补充 `--candidate-profile active_execution_strategy`

### 5.2 查看最近执行历史

- 页面路径：`作业`
- 重点看状态、开始时间、完成时间、标签

### 5.3 恢复失败作业

- 页面路径：`作业详情`
- 按钮：`按记录元数据恢复`
- 恢复后会生成新的 `job_id`

### 5.4 清理失效锁

- 页面路径：`运行时`
- 按钮：`强制解锁`
- 只在确认旧作业已经不再运行时使用

### 5.5 训练连续策略

- 页面路径：`任务`
- 任务名：`continuous-policy-train`
- 常见做法：先用较短窗口做 smoke 训练，再逐步扩大时间区间和股票池
- 如果要切换生命周期风格，优先改 `label_preset`：
  - `balanced_v2`：当前平衡版
  - `swing_v2`：当前收益 / Sharpe 最强的正式 shadow 参考
  - `defensive_v2`：当前更保守，但可能明显压低收益

### 5.6 跑连续策略正式协议

- 页面路径：`任务` 或 `连续策略`
- 任务名：`continuous-policy-protocol`
- 推荐顺序：`train -> evaluate -> shadow continuity -> export`
- 正式示例窗口：`2024-01-02 -> 2025-12-31` 训练、`2026-01-02 -> 2026-04-13` 评估、`2026-04-01 -> 2026-04-13` shadow continuity
- 重点看：连续策略收益指标、连续性指标、active manifest 对照、`policy_v5b` 对照
- 当前还要额外重点看：
  - `hold_share` 是否仍接近 `0`
  - `cash_timing_quality_1d` 是否仍接近 `0`
  - `avg_turnover` 是否仍明显高于 active manifest

### 5.7 评估连续策略

- 页面路径：`任务` 或 `连续策略`
- 任务名：`continuous-policy-evaluate`
- 重点看年化收益、Sharpe、最大回撤、平均换手，以及 teacher / manifest 参考对照

### 5.8 导出连续策略影子动作

- 页面路径：`任务` 或 `连续策略`
- 任务名：`continuous-policy-export`
- 导出后检查 `daily_live_action_panel.csv`、`daily_execution_reasoning.json` 和运行时状态是否一致

### 5.9 管理模拟账户

- 页面路径：`模拟账户`
- 常见做法：先更新现金与持仓，再保存；如果只是演示或联调，可直接使用“重置示例账户”

## 6. 排障建议

### 页面打不开

- 先确认启动命令是否用的是 `yolos`。
- 再确认端口是否被占用。

### 体检不是正常

- 优先修环境、manifest、持仓文件或依赖缺失。
- 不要带着异常状态直接重跑任务。

### 作业一直阻塞

- 去“运行时”页看锁归属和活动线程。
- 如果锁是 stale lock，再执行强制解锁。

### 作业成功但结果不对

- 不要只看退出码。
- 继续检查 `latest_trade_plan.txt`、相关 manifest 和输出目录。

### 连续策略页面没有数据

- 先确认是否已经至少执行过一次 `continuous-policy-protocol`、`continuous-policy-train`、`continuous-policy-evaluate` 或 `continuous-policy-export`。
- 再检查 `daily_research/output/continuous_policy` 下的最新 summary JSON 是否存在。
- 如果导出成功但页面为空，再检查运行时文件和 action panel CSV 是否损坏。

## 7. 高风险提醒

- 不要把控制台改成公网监听。
- 不要绕过 `yolos` 直接使用当前 shell Python。
- 不要在旧作业仍存活时强制解锁。
