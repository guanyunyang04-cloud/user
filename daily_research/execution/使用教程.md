# Daily Research 执行控制台使用教程

权威操作真源：`daily_research/brain/operations_center.md`。本教程只保留面向使用者的简体中文操作说明，不替代 brain 中的当前状态、治理规则和实验结论。

## 1. 使用前提

- 所有 `daily_research` 程序都必须在 `yolos` 环境下运行。
- 依赖环境真源是 `daily_research/environment.yml`。
- 如果本机环境刚调整过，先同步环境：

```powershell
conda env update -f daily_research/environment.yml --prune
```

## 2. 启动方式

自动盘后执行不由 Web 进程负责。每日计划的自动触发主体是 Windows Task Scheduler，触发单次 daily runner：

```powershell
C:/Users/ASUS/miniconda3/envs/yolos/python.exe -m daily_research.execution.daily_plan_runner --mode post-close --json
```

安装、查看和卸载系统任务：

```powershell
C:/Users/ASUS/miniconda3/envs/yolos/python.exe -m daily_research.execution.scheduler_cli install --time 15:45
C:/Users/ASUS/miniconda3/envs/yolos/python.exe -m daily_research.execution.scheduler_cli status --json
C:/Users/ASUS/miniconda3/envs/yolos/python.exe -m daily_research.execution.scheduler_cli uninstall
```

手动预检可以用 dry-run。dry-run 会写 daily verdict，但不会生成新交易计划：

```powershell
C:/Users/ASUS/miniconda3/envs/yolos/python.exe -m daily_research.execution.daily_plan_runner --mode dry-run --json
```

Web 控制台只负责展示 daily verdict、系统任务状态、readiness、作业和手动触发入口。

推荐直接使用独立入口：

```powershell
conda run -n yolos python daily_research/execution/run_execution_web.py --port 8765
```

也可以通过统一应用入口启动：

```powershell
conda run -n yolos python daily_research/execution/run_execution_app.py web --port 8765
```

启动后在浏览器打开：

```text
http://127.0.0.1:8765
```

说明：

- 控制台默认只监听 `127.0.0.1`。
- 不要改成公网地址对外暴露。
- 如果 React build 不存在，页面会返回 `404`，不再回退到 Jinja 模板页。

## 3. 页面说明

### 总览

- 查看最新 daily verdict、目标交易日、阻断原因、交易计划、模拟账户和最近作业。
- 每日盘后计划是否完成，以 `daily_research/output/execution_app/daily_runs/YYYYMMDD/verdict.json` 为准。

### 模型

- 集中查看 live、production、research、legacy 模型卡片。
- 模型训练距交易日多久只做信息展示，不做预警、阻断或自动重训。
- production 重训必须手动确认后提交。

### 数据

- 查看 data platform refresh、lake dataset、provider health、production signal panel 和 readiness 阻断。
- 数据页的手动刷新只作为人工操作；自动盘后链路由 daily runner 串联 readiness、数据刷新、信号刷新、交易计划和 paper reconcile。

### 交易计划

- 查看结构化动作表、持仓、watchlist、模型信息和 TXT 原文。
- 手动生成交易计划仍可用，但不等同于每日计划 completed；每日 completed 必须来自 daily verdict。

### 作业

- 查看最近作业列表和 daily runner 手动触发出来的作业。
- 页面轮询只用于观察作业状态，不承担盘后自动调度。

### 作业详情

- 查看 stdout / stderr 尾部。
- 查看命令、解释器、标签、退出码。
- 对失败或阻塞作业执行恢复。

### 体检

- 检查环境、manifest、持仓文件、运行时目录、Web 依赖、系统任务状态和 daily verdict 证据路径。

### 账户

- 在前端维护 `available_cash` 与模拟持仓。
- 保存后会写回 `daily_research/execution/current_positions.csv`。
- 也可以一键重置为示例账户。

### 系统

- 查看 doctor、锁状态、Windows Task Scheduler、latest daily verdict 和关键证据路径。
- 在确认旧作业已经失效后，可以执行强制解锁。
- 系统页不再展示完整 Runtime JSON；旧 runtime 只作为归档证据。

## 4. 推荐操作顺序

1. 先看“总览”的 Daily Verdict。
2. 如果是 `completed`，再看交易计划、模拟账户和作业证据路径。
3. 如果是 `blocked`，优先看 `blocker_code`、`stage_results` 和 `evidence_paths`。
4. 如果没有最新 verdict，先运行 `daily_plan_runner --mode dry-run --json` 或检查系统任务是否安装。
5. 只有在明确需要人工补救时，才去“数据”“交易计划”“作业详情”提交单项任务。

## 5. 常见操作

### 5.1 查看今日 daily verdict

```powershell
C:/Users/ASUS/miniconda3/envs/yolos/python.exe -m daily_research.execution.daily_plan_runner --mode dry-run --json
```

或者在 Web 总览 / 系统页查看 latest daily verdict。

### 5.2 安装盘后系统任务

```powershell
C:/Users/ASUS/miniconda3/envs/yolos/python.exe -m daily_research.execution.scheduler_cli install --time 15:45
```

### 5.3 检查数据 readiness

- 页面路径：`数据`
- API：`GET /api/data-readiness`
- 若目标交易日 `market_daily` 为空，系统写 `blocked:data_not_ready`，不生成新计划。

### 5.4 生成默认交易计划

- 页面路径：`交易计划`
- 任务名：`trade-plan`
- 常见做法：直接提交，或补充 `--candidate-profile active_execution_strategy`

### 5.5 刷新数据

- 页面路径：`数据`
- 任务名：`data-platform-refresh`
- 常见做法：选择 as-of 日期、股票池和 domains 后显式提交

### 5.6 查看最近执行历史

- 页面路径：`作业`
- 重点看状态、开始时间、完成时间、标签

### 5.7 恢复失败作业

- 页面路径：`作业详情`
- 按钮：`按记录元数据恢复`
- 恢复后会生成新的 `job_id`

### 5.8 清理失效锁

- 页面路径：`系统`
- 按钮：`强制解锁`
- 只在确认旧作业已经不再运行时使用

### 5.9 管理模拟账户

- 页面路径：`账户`
- 常见做法：先更新现金与持仓，再保存；如果只是演示或联调，可直接使用“重置示例账户”

## 6. 排障建议

### 页面打不开

- 先确认启动命令是否用的是 `yolos`。
- 再确认端口是否被占用。

### 体检不是正常

- 优先修环境、manifest、持仓文件或依赖缺失。
- 不要带着异常状态直接重跑任务。

### 作业一直阻塞

- 去“运行时”页看锁归属和活动线程。
- 如果锁是 stale lock，再执行强制解锁。

### 作业成功但结果不对

- 不要只看退出码。
- 继续检查 `latest_trade_plan.txt`、相关 manifest 和输出目录。

### Daily verdict blocked

- `scheduler_not_installed` / `scheduler_disabled`：检查 Windows Task Scheduler 任务 `DailyResearchDailyPlan`。
- `data_not_ready`：检查 `stage_results.data_readiness` 和 `evidence_paths.refresh_manifest`。
- `data_refresh_failed`、`signal_refresh_failed`、`trade_plan_failed`、`paper_reconcile_failed`：进入对应 job detail 和 evidence path 排障。
- 不允许自动回退到前一交易日生成“今日计划”。

## 7. 高风险提醒

- 不要把控制台改成公网监听。
- 不要绕过 `yolos` 直接使用当前 shell Python。
- 不要在旧作业仍存活时强制解锁。
- 不要把旧 runtime 当成新 daily status 的事实来源。
- 不要在目标日行情为空时用上一完整交易日伪装今日 completed。
- 不要把 production 重训、active manifest 写入或 promotion 当成默认动作；这些操作必须显式提交并确认。
