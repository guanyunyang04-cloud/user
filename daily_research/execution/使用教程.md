# Daily Research 执行控制台使用教程

权威操作真源：`daily_research/brain/operations_center.md`。本教程只保留面向使用者的简体中文操作说明，不替代 brain 中的当前状态、治理规则和实验结论。

## 1. 使用前提

- 所有 `daily_research` 程序都必须在 `yolos` 环境下运行。
- 依赖环境真源是 `daily_research/environment.yml`。
- 如果本机环境刚调整过，先同步环境：

```powershell
conda env update -f daily_research/environment.yml --prune
```

## 2. 启动方式

推荐直接使用独立入口：

```powershell
conda run -n yolos python daily_research/execution/run_execution_web.py --port 8765
```

也可以通过统一应用入口启动：

```powershell
conda run -n yolos python daily_research/execution/run_execution_app.py web --port 8765
```

启动后在浏览器打开：

```text
http://127.0.0.1:8765
```

说明：

- 控制台默认只监听 `127.0.0.1`。
- 不要改成公网地址对外暴露。

## 3. 页面说明

### 总览

- 查看当前作业、锁状态、`yolos` 解释器、active manifest、最近作业和最新交易计划。

### 模型

- 集中查看 live、production、research、legacy 模型卡片。
- 模型训练距交易日多久只做信息展示，不做预警、阻断或自动重训。
- production 重训必须手动确认后提交。

### 数据

- 查看 data platform refresh、lake dataset 和当前可用数据边界。
- 数据刷新必须由用户显式提交。

### 交易计划

- 查看结构化动作表、持仓、watchlist、模型信息和 TXT 原文。
- 生成交易计划必须由用户显式提交，不会因为模型训练间隔自动触发重训。

### 作业

- 查看最近作业列表。
- 自动刷新，适合确认作业是否从排队中进入运行中并最终结束。

### 作业详情

- 查看 stdout / stderr 尾部。
- 查看命令、解释器、标签、退出码。
- 对失败或阻塞作业执行恢复。

### 体检

- 检查环境、manifest、持仓文件、运行时目录、Web 依赖和产物文件是否正常。

### 账户

- 在前端维护 `available_cash` 与模拟持仓。
- 保存后会写回 `daily_research/execution/current_positions.csv`。
- 也可以一键重置为示例账户。

### 系统

- 查看 doctor、runtime、锁状态、活动线程、运行时告警和 JSON 快照。
- 在确认旧作业已经失效后，可以执行强制解锁。

## 4. 推荐操作顺序

1. 先打开“体检”页，确认状态为正常。
2. 再去“模型”“数据”或“交易计划”页提交目标任务。
3. 提交后进入“作业详情”页观察日志。
4. 作业结束后到“交易计划”或相关产物页确认结果。
5. 如果失败，再根据 stderr 和运行时状态决定是否恢复。

## 5. 常见操作

### 5.1 生成默认交易计划

- 页面路径：`交易计划`
- 任务名：`trade-plan`
- 常见做法：直接提交，或补充 `--candidate-profile active_execution_strategy`

### 5.2 刷新数据

- 页面路径：`数据`
- 任务名：`data-platform-refresh`
- 常见做法：选择 as-of 日期、股票池和 domains 后显式提交

### 5.3 查看最近执行历史

- 页面路径：`作业`
- 重点看状态、开始时间、完成时间、标签

### 5.4 恢复失败作业

- 页面路径：`作业详情`
- 按钮：`按记录元数据恢复`
- 恢复后会生成新的 `job_id`

### 5.5 清理失效锁

- 页面路径：`系统`
- 按钮：`强制解锁`
- 只在确认旧作业已经不再运行时使用

### 5.6 管理模拟账户

- 页面路径：`账户`
- 常见做法：先更新现金与持仓，再保存；如果只是演示或联调，可直接使用“重置示例账户”

## 6. 排障建议

### 页面打不开

- 先确认启动命令是否用的是 `yolos`。
- 再确认端口是否被占用。

### 体检不是正常

- 优先修环境、manifest、持仓文件或依赖缺失。
- 不要带着异常状态直接重跑任务。

### 作业一直阻塞

- 去“运行时”页看锁归属和活动线程。
- 如果锁是 stale lock，再执行强制解锁。

### 作业成功但结果不对

- 不要只看退出码。
- 继续检查 `latest_trade_plan.txt`、相关 manifest 和输出目录。

## 7. 高风险提醒

- 不要把控制台改成公网监听。
- 不要绕过 `yolos` 直接使用当前 shell Python。
- 不要在旧作业仍存活时强制解锁。
- 不要把 production 重训、active manifest 写入或 promotion 当成默认动作；这些操作必须显式提交并确认。
