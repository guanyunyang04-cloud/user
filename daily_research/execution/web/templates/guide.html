上手路径

按固定顺序使用控制台，能把误操作和无效排查降到最低。

推荐顺序是：先确认环境，再做体检，然后启动任务，最后到作业页和运行时页监控与恢复。

环境
固定使用 yolos
入口
run_execution_web.py
监听地址
127.0.0.1

{{ tutorial_markdown_path }}

第一步

启动前检查

  • 确认当前程序运行在 yolos 环境中。不要依赖当前 shell 恰好激活了什么环境。
  • 如果刚升级过环境，先执行 conda env update -f daily_research/environment.yml --prune。
  • 用 python daily_research/execution/run_execution_app.py doctor 或控制台的“体检”页确认关键依赖、manifest、持仓和运行时目录正常。

第二步

启动控制台

conda run -n yolos python daily_research/execution/run_execution_web.py --port 8765
  • 浏览器打开 http://127.0.0.1:8765。
  • 如果你更习惯统一入口，也可以使用 python daily_research/execution/run_execution_app.py web --port 8765。

第三步

页面职责分工

  • 总览：看当前作业、锁状态、active manifest、最近作业和最新交易计划。
  • 任务：从注册表里选择任务，填写表单参数，后台提交执行。
  • 作业：查看最近作业列表，确认状态是否从排队中进入运行中并最终结束。
  • 作业详情：跟踪 stdout/stderr，必要时对失败或阻塞作业执行恢复。
  • 体检：检查依赖、运行时、manifest、持仓和关键产物是否齐全。
  • 交易计划：预览 latest_trade_plan.txt 内容。
  • 连续策略：查看连续型组合策略代理的最新训练、评估、影子导出和组合运行时状态。
  • 模拟账户：维护可用现金和模拟持仓，用于交易计划和连续策略影子导出的账户输入。
  • 运行时：查看锁、活动线程、告警与完整 JSON 快照，并在确认作业失效后执行强制解锁。

第四步

推荐操作流程

  1. 先打开“体检”页。如果状态不是“正常”，优先修环境或输入文件，不要急着重跑任务。
  2. 再去“任务”页启动目标任务。常见入口是 trade-plan、candidate-trade-plan、candidate-backtest。
  3. 提交后自动跳转到作业详情。先看 stdout/stderr 是否正常滚动，再判断是否需要切回总览或作业列表。
  4. 任务结束后查看“交易计划”或相关产物。不要只看作业成功与否，还要确认结果文件内容是否符合预期。
  5. 如果在推进连续策略。优先直接运行 continuous-policy-protocol；它会按 train -> evaluate -> shadow continuity -> export 的顺序串联执行。正式候选默认选 formal_torch_v2，它要求 GPU、至少 32 epoch 和 strict resume；prototype_gbdt_v1 只保留给 shadow / teacher。
  6. 如果要做影子账户联调。先在“模拟账户”页校准现金与持仓，再执行交易计划或连续策略导出，避免输入状态失真。

恢复

失败后的处理方式

  • 作业失败：先看作业详情里的 stderr，再决定是否点击“按记录元数据恢复”。
  • 作业阻塞：先到运行时页检查锁归属和活动线程，确认旧作业确实已经消失后，再执行“强制解锁”。
  • 恢复后会生成新的 job_id。不要把恢复后的作业和原作业当成同一次记录。

注意

高风险操作提示

  • 不要把控制台绑定到公网地址。当前设计就是本地控制面，默认仅监听 127.0.0.1。
  • 不要在未确认旧作业退出时强制解锁。否则可能出现并发写状态或误覆盖结果。
  • 不要绕过 yolos 直接用当前 shell Python。环境漂移会被误判成代码故障。
