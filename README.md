# QuantLab

QuantLab is a personal A-share research workspace. It provides a point-in-time
data store, causal feature/label builders, and replay tools for evaluating
cross-sectional signals. The repository contains research infrastructure, not
a trading service. No live orders are sent by this project.

## Working rules

- Information available at a decision timestamp is the only permitted model
  input. Outcome data is never used to construct same-day features.
- Suspension, limit, T+1, fees, slippage, lot size, cash, and participation
  constraints are explicit contract fields.
- Results are evidence about a specified sample and execution model. A positive
  backtest is not a production or profitability claim.
- The current minute study uses 2022-2024 for development and model selection,
  then evaluates 2025 once as a held-out validation period. There is no second
  fold or early-stopping split in this four-year workflow.
- Hand-designed, causal strategies are the next primary research path. Machine
  learning is an optional comparator, not an assumption about the solution.

## Repository map

- `src/quantlab/core`: shared paths, JSON contracts, hashing, and atomic file
  operations.
- `src/quantlab/data/domains/contracts`: domain schemas, requests, and
  normalization boundaries.
- `src/quantlab/data/providers`: provider adapters and frame shaping.
- `src/quantlab/data/qdp_v2`: the active point-in-time data store and its
  update, repair, audit, and maintenance workflows. The `qdp_v2` name is the
  current Python/physical namespace; it is not a second data generation.
- `src/quantlab/research`: daily baselines, minute-v2 builders, the causal
  minute-MA event layer, labels, training, sampling, and replay.
- `data/qdp/qdp_v2`: mutable active QDP datasets and `active/active.json`.
- `data/qdp/source_archives`: immutable downloaded source inputs and repair
  evidence. These files are not regenerated by model runs.
- `data/research`: local generated research products. They are ignored by Git
  except for the daily contract manifest.
- `research/studies`: durable study specifications.
- `research/records`: compact reports and evidence indexes.
- `runs`: local model and evaluation outputs.
- `tools`: bounded migration and maintenance utilities.

The current minute-MA event contract and its real-data representative check are
kept under `research/records/minute_ma_v1/`. The check covers 2022-2024 only;
it validates causal definitions and data completeness, not profitability.
The finite rule/event-study pilot is under
`research/records/minute_ma_v2_pilot/`; its cross-sectional control uses
prior-session turnover matching and its minute outcomes begin at the next-open
fill bar. That pilot is still an eight-symbol implementation check, not a
full-universe result.

Minute-strategy outputs also support additive normalized `events`, `paths`, and
`references` tables for reusing one forward price path across rule and account
comparisons. The performance smoke results and the decision not to enable
unbounded date parallelism are recorded in
`research/records/minute_strategy_performance_benchmarks_v1/`.
The first full-universe April 2022 run with the bounded four-thread/128-symbol
path completed safely; its throughput and memory curve are recorded in
`research/records/minute_strategy_full_month_benchmark_v1/`.
The optional date-parallel memory admission policy is documented in
`research/records/minute_strategy_date_parallel_admission_v1/`; date workers
remain disabled by default.

The former `daily_research/` and `quant_data_platform/` trees are retired.
Historical reports may still mention those names as provenance; such strings
are not runtime imports or active data locations.

## Data contract

The active QDP manifest is
`data/qdp/qdp_v2/active/active.json`. Its current point-in-time cutoff is
2026-07-21. The canonical one-minute store covers 2010-01-04 through the
available 2026-08-21 tail, with approximately 3.30 billion continuous bars
and 13.76 million separate 09:30 rows. The 09:30 domain is retained
separately because a zero-volume opening placeholder is not an auction trade.

BaoStock is the default structured daily source. MootDX and CNInfo support
recent detection and disclosure confirmation. A Tushare-compatible profile and
the purchased local archive are restricted to audited, field-level minute
repair and cross-validation; they are not blanket replacement sources.

Historical minute quality is represented by per-field masks for open, high,
low, and close, plus independent session and flow checks. Consumers must apply
those masks instead of dropping or silently repairing an entire stock-day.
Active source archives and installed repair evidence are retained under
`data/qdp/source_archives`.

## Minute-v2 research

The active implementation is `quantlab.research.minute_v2`. It evaluates causal
decision bars from 09:31-11:29 and 13:01-14:55 (234 groups per complete day),
with next-bar entry, ordinary-share T+1, legal exits, costs, capacity, and
explicit unavailable labels.

Feature storage is declared in each month manifest:

- `split`: 82 core columns in `base.parquet` plus 97 optional columns in
  `optional_features.parquet`;
- `core`: core columns only, for contract checks or core-only training;
- `full`: all 179 model columns in the base artifact.

`label_*m` advances along the decision grid and therefore means decision steps,
not necessarily elapsed clock minutes. `label_session_*m` stays within one
trade date and marks incomplete or gapped windows. High/low masks affect MFE
and MAE independently from observable close-return labels.

The current builder revision is `2026-08-29-1`. A verified one-day development
artifact is at
`data/research/minute_v2_dev_rev6_partition/months/year=2022/month=06/manifest.json`.
It has 683,748 base rows, 683,748 optional-feature rows, and 254,417 event and
label rows across all 234 groups. The retained compatibility artifact is
`data/research/minute_v2_bench_narrow_rev5/`; it was built under an earlier
revision and must not be edited to match current code.

## Artifact lifecycle

Keep immutable source archives, the active QDP datasets, compact manifests, and
durable research conclusions. Delete or regenerate failed build directories,
temporary support caches, raw predictions, and expanded workflow captures only
after their manifest or archive has been verified. Use the manifest-first dry
run before collecting unreferenced QDP generations:

```powershell
$env:PYTHONPATH='H:\quant_project\src'
C:/Users/ASUS/miniconda3/envs/yolos/python.exe -m quantlab data gc `
  --workspace-root H:/quant_project --with-size --json
```

The retired full-month minute-v2 product and incomplete rev6 build attempts are
documented, with compact evidence, under
`data/research/archive/minute_v2_legacy_20260830/`. Their original manifests
are historical snapshots and must not be used as active inputs.

Never use this cleanup path for `data/qdp/source_archives` or an active QDP
dataset. Runtime archives are checked by hash before expanded sources are
removed; old manifests with the retired root name are resolved beside their
manifest for compatibility.
