# Daily Stock Analysis 教训记忆

快照日期：`2026-04-12`

## L001 - 多入口仓库最容易在边界上失焦
- 事件：
  - 产品同时拥有 CLI、API、Web、Desktop、Bot、多数据源和工作流。
- 场景：
  - 接管者直接从代码树盲扫时。
- 根因：
  - 没先判断任务属于哪条链路。
- 信号：
  - 同一轮改动同时碰多个入口，但缺少清晰主线。
- 影响：
  - 改动扩散、验证混乱、接管成本高。
- 修复：
  - 先用 brain 锁定 body 边界。
- 预防：
  - 当前接管默认先读交接包，再定位入口。
- 升级动作：
  - 写入 action system 和 governance layer。

## L002 - brain 与仓库原生 AI 资产需要并存而不是互斥
- 事件：
  - 仓库内已有 `AGENTS.md / CLAUDE.md` 等协作资产。
- 场景：
  - 工作区主脑引入后。
- 根因：
  - 容易误以为只保留一种入口就够了。
- 信号：
  - brain 与 body 级 AI 资产的职责不清。
- 影响：
  - 接管入口冲突，规则容易分裂。
- 修复：
  - 明确 brain 是工作区级入口，`AGENTS.md / CLAUDE.md` 是 body 级资产。
- 预防：
  - 结构调整时同步维护两层，但保持主次分明。
- 升级动作：
  - 写入身份层、规则记忆和程序记忆。
